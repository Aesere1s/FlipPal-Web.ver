# FlipPal — 把理解翻出来

> 不是收藏答案，而是交换理解。

FlipPal 是一个本地优先的卡片学习与表达 Web Demo。它通过每日抽卡、翻卡阅读、限时小测和自主改写，把“我看过”推进为“我能讲清楚”；可定制的 OC（Original Character）则作为第一位读者，用不同性格的反馈陪伴学习者完成表达。

项目当前定位为比赛作品 Demo，采用 React 单页应用实现，无需注册、无需后端服务即可体验。当前主应用已完成抽卡、学卡、改卡与 OC 创建，漂流、逐句批注和成长结算仍属于后续开发内容。

## 一、项目背景

学习中常见的问题并不是缺少内容，而是内容停留在“收藏”和“看过”：

- 面对大量资料，不知道今天应该从哪里开始；
- 阅读时觉得已经理解，合上内容后却无法复述；
- 小测答对并不等于能够用自己的话解释；
- 独自学习缺少持续反馈，也难以感知自己的成长。

FlipPal 将一次学习过程压缩为一张卡的完整循环：先通过抽卡降低选择成本，再通过提问、解释和小测检查理解，最后要求学习者重写问题、解释、例子与来源。项目希望衡量的不是打卡次数，而是学习者是否真正讲明白了一件事。

## 二、产品定位与核心价值

| 维度 | 说明 |
| --- | --- |
| 产品形态 | 浏览器访问的 Web 单页应用 |
| 当前阶段 | 面向比赛展示与答辩演示的 Demo |
| 直接受众 | 比赛评委、答辩观众、项目体验者及开发成员 |
| 产品面向 | 希望借助主动回忆、费曼式输出和反馈检验理解的自学者 |
| 使用成本 | 无需安装、无需账号，打开页面即可开始 |
| 数据方式 | 本地 JSON 内容库与浏览器 localStorage，不依赖云端服务 |

核心价值可以概括为四点：

1. **降低开始成本**：每日三张卡替代“今天学什么”的选择压力。
2. **主动检查理解**：卡面提问、卡背解释和四选一小测组成一个主动学习单元。
3. **推动个人表达**：改卡不是简单摘抄，而是重新组织问题、解释、例子和来源。
4. **提供陪伴感**：OC 不只是头像，而是根据性格生成问候与改卡反馈的第一位读者。

## 三、当前已实现功能

### 3.1 每日抽卡

- 每天生成三张学习卡，同一天内结果可复现；
- 抽卡结果综合本地日期、用户标识、学习记录与掌握度；
- 未学习卡片具有更高权重，连续未获得新卡时提供新卡保底；
- 支持逐张翻牌和一次重抽，重抽只替换尚未翻开的卡位；
- 稀有度影响卡面角标、边框与阴影，不影响抽卡权重或成长数值。

### 3.2 翻卡学习与小测

- 通过 CSS 3D 翻卡切换正面问题与背面解释；
- 卡背包含概念说明、适用边界或反例，以及内容来源；
- 翻面后开启 60 秒四选一小测；
- 页面失焦或隐藏时暂停计时，返回后继续；
- 作答后展示正确答案及卡背原文依据；
- 记录今日学习进度和卡片掌握度，答错或超时不会降低已有掌握度。

### 3.3 改卡与 OC 规则挑刺

学习者可以在原卡对照下编辑四个内容槽位：

| 槽位 | 内容要求 | 长度上限 |
| --- | --- | ---: |
| 正面 | 重新组织问题 | 60 字 |
| 解释 | 用自己的话说明概念 | 600 字 |
| 例子 | 加入个人经验或具体场景 | 400 字 |
| 来源 | 标明可追溯的内容出处 | 120 字 |

改卡模块支持草稿保存、非空与长度校验，以及可解释的本地规则反馈：

- 检测是否连续照抄原卡内容；
- 检查是否包含第一人称、时间、地点或学习工作场景等个人化表达；
- 检查来源是否具体到章节、文章、课程或视频等信息；
- 按优先级返回一个主要问题，并引用相关文本片段；
- 根据 OC 性格使用不同话术，避免反馈只有统一的系统提示。

当前挑刺全部由同步本地规则完成，不调用生成式 AI。用户改写的内容保存在独立版本中，不会覆盖官方卡片，也不会自动进入抽卡卡池。

### 3.4 OC 创建与陪伴

OC 创建采用四步流程：性格、声线说明、外观、确认。

- 三种性格：沉静、好奇、犀利；
- 四类外观部件：脸型、发型、配色、服饰，每类提供四种选择；
- 支持随机搭配、实时 SVG 预览、保存后重新编辑；
- 第一句话会结合性格与外观变量生成；
- 首页、学卡和改卡页面复用同一套 OC 气泡反馈。

“声线”当前表示文字规则与台词风格，不包含语音播放或 TTS。

### 3.5 本地保存与演示重置

- 抽卡记录、掌握度、OC 和已保存改卡可跨刷新恢复；
- 持久化数据带有 schema 版本校验，版本不匹配或数据损坏时会安全重建；
- 顶部提供“重置演示”二次确认；
- 支持通过 `?demo=fresh` 重置演示状态，并保留当前路径及其他 URL 参数；
- localStorage 不可用时可退化为内存状态，但刷新后不再保证保留。

### 3.6 内部卡池浏览

`/cards` 提供内部调试与内容检查页面，可按方向筛选卡片、展开卡背和小测、查看答案依据及内容资产统计。该页面用于开发验收，不属于顶部主导航。

## 四、核心使用流程

当前 React 主应用可完成以下流程：

    创建 OC（可选）
      → 首页进入今日抽卡
      → 翻牌查看卡面与来源
      → 进入学卡并阅读卡背
      → 完成 60 秒四选一小测
      → 查看答案、原文依据与掌握度
      → 进入改卡并保存草稿
      → 提交给 OC 进行规则挑刺
      → 根据反馈继续修改

流程并非强制串行：不创建 OC 也可以抽卡和学卡；通过有效卡片 URL 可以直接进入学卡或改卡。没有 OC 时仍可保存改卡草稿，但正式提交前需要先创建 OC。

产品完整概念路线为“抽卡 → 学卡 → 改卡 → 漂流 → 成长”。其中前三站已接入主应用，后两站仍待实现。

## 五、内容设计

当前内置 24 张官方学习卡，覆盖三个方向，每个方向 8 张：

| 学习方向 | 内容侧重 |
| --- | --- |
| 认知与思维 | 认知偏差、决策方式与思维工具 |
| 编程与工具 | 编程概念、开发方法与工具使用 |
| 表达与沟通 | 表达结构、沟通方式与协作理解 |

每张卡包含方向、标题、正面问题、背面解释、来源、难度、稀有度和四选一小测。小测的答案依据必须是卡背原文中的连续片段，以保证题目反馈能够回到具体内容，而不是只显示对错。

当前难度覆盖 2—4 级，稀有度分为普通、稀有和跨界。卡片使用本地 JSON 维护，并通过构建前脚本检查数量、字段、长度、ID 唯一性、选项与答案依据等结构约束。

## 六、技术实现

### 6.1 技术栈

| 层次 | 技术方案 |
| --- | --- |
| 前端框架 | React 18 + React DOM |
| 开发语言 | TypeScript，开启严格类型检查 |
| 构建工具 | Vite 6 |
| 路由 | React Router DOM，使用 BrowserRouter 模式 |
| 状态管理 | Zustand + persist |
| 内容数据 | 本地 JSON |
| 数据持久化 | 浏览器 localStorage |
| 样式与动效 | 原生 CSS、CSS 变量、Grid、CSS 3D |
| 测试与验收 | Node 内置测试器、数据校验脚本、CDP 浏览器验收脚本 |

项目没有引入 Tailwind CSS、Framer Motion 或 UI 组件库，界面与动效均由项目内 CSS 和 React 组件实现。

### 6.2 模块划分

- `src/pages`：首页、抽卡、学卡、改卡、OC、卡池及占位页面；
- `src/components`：翻卡、小测、进度环、OC 头像与气泡等复用组件；
- `src/store/gameStore.ts`：统一状态树、业务 action 与持久化；
- `src/lib/draw.ts`：可独立测试的确定性抽卡纯函数；
- `src/lib/critique.ts`：改卡校验与规则挑刺；
- `src/lib/ocLines.ts`：OC 性格与台词生成；
- `src/data`：官方卡片、OC 预设和预置批注数据；
- `src/styles`：设计令牌、全局样式和各模块样式；
- `scripts`：数据校验、抽卡测试及 L2—L5 浏览器验收脚本。

### 6.3 数据与隐私边界

当前版本没有真实账号、云同步、多用户后端或服务端匹配。学习数据主要保存在当前浏览器中，清除站点数据、更换浏览器或设备后不会自动迁移。OC 反馈和改卡挑刺均在本地执行，不需要把学习文本发送给外部 AI 服务。

## 七、视觉与交互设计

FlipPal 将“报刊、账簿式产品界面”与“温暖的手绘学习小镇”并置，形成具有冲突感的视觉语言：

- 纸张底色 `#f2f0e6`、墨色 `#19201b`、朱橙 `#ff5c35`、雾蓝 `#8fcbd3`；
- 卡纸使用 `#fff9e9`，搭配零圆角和 `7px 7px 0` 硬阴影；
- 七栏编号导航、细线分隔、栅格背景与英文元信息建立报刊感；
- Georgia、宋体类衬线标题与等宽字体标签形成排版对比；
- 首页使用学习小镇插画和五站路线图，将学习流程转化为可步行的地点；
- OC 使用内联 SVG 几何部件组合，保证外观预览与状态一致；
- 抽卡和学卡使用 `preserve-3d`、`backface-visibility` 与 `rotateY()` 实现翻面；
- 主要响应式断点为 900px 和 760px，并支持 `prefers-reduced-motion`；
- 提供跳到主内容链接、`focus-visible` 样式及语义化 ARIA 标签。

## 九、本地运行

### 9.1 环境要求

- Node.js `>= 22.6.0`
- npm

### 9.2 安装与启动

在项目根目录执行：

    npm ci
    npm run dev

开发服务器默认监听 `0.0.0.0:5173`，本机可通过 `http://localhost:5173` 访问。

### 9.3 构建与预览

    npm run build
    npm run preview

`npm run build` 会依次执行卡片数据校验、TypeScript 类型检查和 Vite 正式构建。预览服务器默认使用 4173 端口。

### 9.4 质量检查

    npm run validate:cards
    npm run typecheck
    npm run test:draw

浏览器验收脚本按功能层级拆分：

    npm run verify:l2
    npm run verify:l3
    npm run verify:l4
    npm run verify:l5

这些脚本分别覆盖抽卡、学卡、OC 和改卡流程，依赖本地开发服务器及开启 Chrome DevTools Protocol 的浏览器，具体启动方式以对应脚本为准。

## 十、部署说明

项目已包含 Netlify 与 Vercel 的 SPA 配置：

- Netlify 使用 `npm run build` 构建并发布 `dist`；
- Vercel 将路径重写到 `index.html`；
- 由于使用 BrowserRouter，部署平台必须配置 SPA fallback，否则直接刷新子路由可能返回 404；
- 不建议直接双击 `dist/index.html` 作为完整演示方式。

仓库未提供已确认的线上 Demo 地址，部署后应以实际平台生成的地址为准。

## 十二、Demo 边界与后续方向

为避免把规划误认为现有能力，当前边界如下：

| 项目 | 当前状态 |
| --- | --- |
| 漂流寄出与可操作收件箱 | 尚未接入 React 主应用 |
| 逐句批注与回信 | 已有预置 JSON 数据，主流程 UI 尚未实现 |
| 成长值结算与成长树 | 尚未实现 |
| 掌握度 3、关系升级与能力解锁 | 类型或状态字段预留，尚无完整可达流程 |
| AI 挑刺、AI 批注与 AI OC 台词 | 未接入，当前使用本地规则与模板 |
| OC 语音与 TTS | 未实现 |
| 真实账号、云同步与多用户服务 | 不在当前 Demo 范围内 |
| 分享卡导出与学习统计面板 | 尚未实现 |
| About 答辩页 | 占位页 |

`design/prototype.html` 是独立的概念原型，使用另一套数据和本地存储键，模拟了寄出、回信与成长等完整概念流程。这些模拟能力不能视为 React 主应用已经交付的功能。

后续开发将沿用 L0—Ln 的分级路线，优先补齐漂流、批注、回信和成长结算，使“抽到—读懂—讲清楚—寄出去—带回反馈”的学习闭环在主应用中真正贯通。

## 十三、一句话总结

FlipPal 不是把更多答案装进收藏夹，而是用一张卡、一次表达和一位有性格的读者，帮助学习者把模糊的理解翻出来、讲清楚，并最终交换给另一个人。
